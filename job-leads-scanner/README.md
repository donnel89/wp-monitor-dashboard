# סורק לידים ממודעות דרושים

הכלי סורק מודעות דרושים של קמפיינרים ואנשי שיווק דיגיטלי. הוא מזהה מי מהמפרסמים הוא **עסק שמגייס לעצמו** (ליד) ומי הוא **סוכנות** (מתחרה), ומכין לכל ליד טיוטת מייל עם הצעה לצוות מלא במיקור חוץ: קמפיינר, עיצוב, דפי נחיתה ותוכן.

## איך מריצים

```bash
cd job-leads-scanner
npm install
npm run scan            # סריקה, סיווג ודוח
```

בסיום נוצרים:
- `report.html`: הדוח. פותחים אותו בדפדפן.
- `data/leads.csv`: הלידים בקובץ CSV, לייבוא ל-monday או לאקסל.
- `data/leads.json`: המאגר המלא. סריקה חוזרת מוסיפה רק מודעות חדשות.

### אפשרויות

| פקודה | מה היא עושה |
|---|---|
| `node src/scan.js --no-ai` | סיווג לפי חוקים בלבד, בלי Claude |
| `node src/scan.js --keywords "קמפיינר,PPC"` | חיפוש במילים אחרות |
| `node src/scan.js --add examples/manual-ads.json` | הוספה ידנית של מודעות מלינקדאין, מפייסבוק וכו' |
| `node src/scan.js --reclassify` | סיווג מחדש של כל המאגר |
| `node src/scan.js --report-only` | בניית הדוח מחדש בלי לסרוק |

## איך הסיווג עובד

לכל מודעה נקבעים שלושה צירים:

| ציר | ערכים | איך מזהים |
|---|---|---|
| **מי פרסם** | חברה ישירה / חברת השמה / חסוי | שם המפרסם, וביטויים כמו "לאחד מלקוחותינו" או "לחברה מובילה" |
| **מי המעסיק** | עסק / סוכנות | "משרד פרסום", "תיקי לקוחות", "לקוחות מתחומים שונים" מצביעים על סוכנות. "מול משרד הפרסום" ו"לצד הלקוח" מצביעים על עסק |
| **רלוונטיות** | כן / לא | האם זה תפקיד קמפיינים או דיגיטל שאפשר להחליף בשירות |

**ציון ליד (0-100):** גבוה לעסקים קטנים ובינוניים שמגייסים תפקיד ביצועי, במיוחד כשהמודעה מבקשת גם דפי נחיתה, עיצוב או תוכן. נמוך לאוניברסיטאות, לבתי חולים, לתאגידים ולתפקידים בכירים. סוכנויות מקבלות 0.

**חברה שזוהתה כסוכנות במודעה אחת שלה מסווגת כסוכנות גם בכל המודעות האחרות שלה.**

### סיווג חכם עם Claude (אופציונלי)

אם מוגדר `ANTHROPIC_API_KEY`, כל מודעה רלוונטית נשלחת ל-Claude. Claude מחזיר ניחוש מדויק יותר של המעסיק האמיתי, וגם **זווית פנייה** מותאמת שנכנסת למייל. בלי מפתח הכלי עובד עם חוקים בלבד.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
npm run scan
```

ההגדרות: מודל `claude-opus-5-5` ברמת מאמץ `low`. בנוסף מופעל `fallbacks: "default"`: אם Claude מסרב לבקשה, היא עוברת אוטומטית למודל חלופי. אפשר לשנות את זה ב-`config.local.json`.

## התאמה אישית

יוצרים קובץ `config.local.json` בתיקיית הפרויקט:

```json
{
  "sender": { "agencyName": "STRA", "senderName": "מעוז", "phone": "050-0000000", "website": "https://..." },
  "keywords": ["קמפיינר", "PPC", "מנהל קמפיינים"],
  "hotLeadScore": 60
}
```

## לפני ששולחים מיילים: חוק הספאם

לפי **סעיף 30א לחוק התקשורת** מותר לפנות **לבית עסק פעם אחת** בבקשה לקבל הסכמה לדיוור. לכן:
- טיוטת המייל מנוסחת כפנייה אישית אחת, שמבקשת רשות לשלוח הצעה וכוללת אפשרות להסיר.
- **שולחים ידנית, אחד אחד.** הכלי לא שולח מיילים בעצמו.
- מי שלא ענה לא מקבל מייל נוסף.

## מקורות

- **Drushim:** נסרק העמוד הציבורי של תוצאות החיפוש, עמוד אחד לכל מילת חיפוש (כ-25 מודעות), עם השהיה בין הבקשות.
- **AllJobs:** מוגן מפני בוטים, ולכן לא נכלל.
- **לינקדאין:** תנאי השימוש שלו אוסרים סריקה. מוסיפים ממנו מודעות ידנית עם `--add`.

## המשך מוצע

1. הרצה יומית אוטומטית (GitHub Actions או cron) עם התראה על לידים חמים חדשים
2. חיבור ל-monday: כל ליד חם הופך לפריט בבורד
3. יצירת טיוטה ב-Gmail ישירות מהדוח
4. העשרת אנשי קשר: איתור אתר החברה ומנהל השיווק
